# screenshots

## Purpose
App and website captures for the report, deck, user guide and store listing.

## Files that must exist
- `app/` — one per screen, real data, dark theme, device frame optional
- `website/`
- `notebook/` — the key figures exported at print resolution
- `scope/` — instrument captures, cross-linked to the test IDs

## Standards
- Captured on a real device at native resolution, not an emulator
- Real values on screen, never placeholder or zeroed
- Status bar clean: full battery, no notifications
- Consistent scenario across the set so numbers agree screen to screen

## Acceptance
The screenshot set tells the whole app story in order without narration. The
numbers visible across screens are mutually consistent, because a judge will
notice if they are not.
