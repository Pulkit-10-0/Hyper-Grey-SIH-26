# demo-script

## Purpose
The six-minute run, written down and rehearsed. Also the recovery path when
hardware fails, because it will.

## Files that must exist
- `demo-script.md` — beat by beat, with timings
- `demo-checklist.md` — the pre-demo five-minute check
- `recovery-plan.md` — what to do when each subsystem dies
- `equipment-list.md` — everything that must be in the bag

## Structure
Each beat carries: elapsed time, what you do, what you say, what the judge
should see, and what to do if it fails.

## The beats
| Time | Beat |
|---|---|
| 0:00 | Hand over the compliance matrix |
| 0:30 | The traditional fixed ping, with its resolution |
| 1:15 | The chirp, and the compressed peak |
| 2:15 | A judge changes the water; the payload adapts unaided |
| 3:15 | Window toggled, sidelobes measured live |
| 4:00 | Phase-coded mode |
| 4:45 | Power, and the CPU idle trace |
| 5:30 | Open the pod, hand over the test report |

## Acceptance
Rehearsed three times to the clock. One rehearsal must include a deliberate
hardware kill and a recovery. A second team member must be able to run the
whole thing alone.

## What went wrong last year
There was no written demo script in the repository.
