# ios-build-notes

Everything needed to turn this source into an installable iOS build, written so
that whoever gets access to a Mac does not have to work any of it out.

## 2. How `ios/` was generated on Windows

The Expo CLI explicitly refuses to write iOS project files from Windows:

```
Skipping generating the iOS native project files.
Run npx expo prebuild again from macOS or Linux to generate the iOS project.
CommandError: At least one platform must be enabled when syncing
```

The check is on the host OS, not on the availability of a compiler, so the
project can be generated from Linux even though it cannot be built there. WSL
was used, with a Linux Node unpacked **inside the project's own `.toolchain/`
folder** so that nothing was installed system-wide and the whole setup can still
be removed by deleting one directory:

```bash
# One-time: put a Linux Node inside the project, not on the system
cd .toolchain
curl -O https://nodejs.org/dist/v22.20.0/node-v22.20.0-linux-x64.tar.xz
mkdir -p node-linux && tar -xJf node-v22.20.0-linux-x64.tar.xz \
  -C node-linux --strip-components=1

# Generate the project
cd ..
export PATH="$PWD/.toolchain/node-linux/bin:$PATH"
node node_modules/expo/bin/cli prebuild --platform ios --no-install
```

`--no-install` skips `pod install`, which would fail on Linux.

The Linux Node lives at `.toolchain/node-linux/`, alongside the Windows Node,
JDK and Android SDK. Deleting `.toolchain/` removes every tool this project
downloaded; nothing was installed system-wide, in WSL or on Windows.

To regenerate after changing `app.json`, repeat the command. It clears `ios/`
and rebuilds it from the config — so never hand-edit the Xcode project.

## 3. The blocker, precisely

Three separate requirements, only the third of which costs money:

1. **Xcode.** Ships only for macOS. Provides `clang` targeting
   `arm64-apple-ios`, the iOS SDK, `xcodebuild`, and the archive/export
   pipeline. No supported cross-compiler exists.
2. **CocoaPods.** Resolves and builds the native modules this app depends on —
   React Native core, Hermes, Skia, Reanimated, Gesture Handler, and the Expo
   modules. Each compiles Objective-C, Swift and C++ against the iOS SDK.
3. **An Apple signing identity.** Required for anything that runs on a physical
   device. Apple Developer Program membership is roughly ₹9,000 a year.

Item 3 is not needed for a Simulator build. Items 1 and 2 always are.

## 4. Route A — a macOS machine

Prerequisites: macOS 14 or later, Xcode 16 or later with command line tools,
Node 22, CocoaPods.

```bash
npm install
npx pod-install                # wrapper for: cd ios && pod install
```

Commit the `ios/Podfile.lock` that this produces. It is the only thing that makes
two machines install identical pod versions, and it cannot be generated anywhere
else.

### Simulator build — no Apple account needed

```bash
npx expo run:ios --configuration Release
```

Produces a `.app` that runs in the iOS Simulator. Good enough to demonstrate the
app and to screenshot; it will not install on a phone.

### Device build and `.ipa`

```bash
open ios/SeaNergy.xcworkspace
```

Note: the **workspace**, not the `.xcodeproj`. Opening the project directly
misses the pods and the build fails with missing headers.

In Xcode:

1. Select the `SeaNergy` target → Signing & Capabilities
2. Set **Team** to your Apple Developer team; leave *Automatically manage
   signing* on
3. Confirm the bundle identifier reads `in.seanergy.console`
4. Choose *Any iOS Device (arm64)* as the destination
5. Product → Archive
6. In the Organiser: Distribute App → *Ad Hoc* (a handful of registered devices)
   or *App Store Connect* (TestFlight)

Ad Hoc requires each test device's UDID registered in the developer portal
before the profile is created. TestFlight does not, and is easier for judges.

Export as `SeaNergy-2.1.0___ios.ipa` and place it in `../releases/` alongside the
Android packages.

## 5. Route B — EAS cloud build, no Mac required

Expo compiles on its own macOS fleet.

```bash
npm install -g eas-cli
eas login
eas build:configure
eas build --platform ios --profile preview
```

`eas build:configure` writes `eas.json`. A minimal profile:

```json
{
  "build": {
    "preview":    { "distribution": "internal", "ios": { "simulator": false } },
    "simulator":  { "ios": { "simulator": true } },
    "production": { "autoIncrement": true }
  }
}
```

- `--profile simulator` needs **no Apple account** and returns a Simulator build.
- `--profile preview` returns an installable `.ipa` but requires Apple credentials;
  EAS will prompt for them and can generate the certificate and profile for you.
- Registered devices for internal distribution: `eas device:create`.

Cost: the free tier queues; a paid tier does not. Build time is roughly 15 to 25
minutes for a project this size.

**This is the recommended route** if an Apple account is obtained before the
finals. It needs no hardware.

## 6. Decision, and why

| Option | Hardware | Apple account | Installs on a phone | Chosen |
|---|---|---|---|---|
| Ship nothing, claim nothing | none | no | — | **Yes, for now** |
| Simulator build via EAS | none | no | no | Fallback for screenshots |
| `.ipa` via EAS | none | yes | yes | If an account is obtained |
| `.ipa` via a borrowed Mac | Mac | yes | yes | Equivalent |

We are not going to put an Android APK in this folder and rename it. The 2025
submission did exactly that — an Android project inside a folder named `ios` —
and it is the single easiest thing for a reviewer to catch.

## 7. Risks once the build does happen

Things that are known to bite on the first iOS build of a project like this, so
nobody loses an afternoon to them:

| Risk | Detail | Mitigation |
|---|---|---|
| Skia build time | `@shopify/react-native-skia` compiles a large C++ surface | Expect a long first build; the second is cached |
| Reanimated worklets | Version must match the React Native version exactly | Already pinned: Reanimated 4.5.1, worklets 0.10.1, RN 0.86.2 |
| Hermes vs JSC | Bundle format differs | Hermes is already selected in `Podfile.properties.json` |
| Missing `Podfile.lock` | Two machines resolve different pod versions | Commit the lock file the first time it is generated |
| New Architecture | `newArchEnabled: true` in `app.json` | Every dependency here already supports it; the Android build confirms it |
| Portrait lock | `expo-screen-orientation` plugin is configured | Verify on an iPad, where iOS is less willing to honour it |
| Fonts | Rajdhani and JetBrains Mono are bundled, not fetched | Confirm they appear in *Copy Bundle Resources* after `pod install` |
